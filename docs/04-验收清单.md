# 验收清单（上板逐项回填）

> 用法：按顺序做，每项把"实测"一列填掉；不符合预期时把串口原文贴回来。
> 约定：`>` 表示串口输入的命令，其余为板子输出。
> **AI 不代替验收**：编译、下载、断电、晃动、遮光这些动作必须在板子上完成。

---

## 0. 前置与上电自检

1. Keil MDK5 + **AC5 V5.06u7** + MicroLIB，打开 `MDK-ARM/demo2_1.uvprojx`；
2. Rebuild → **0 Error / 0 Warning**；
3. 下载（Reset and Run），串口 115200-8-N-1。

**预期首屏**（顺序可能略有差异）：

```
 P0 Logger  -  STM32H743XIH6
 USART1 @115200 8-N-1
 built: ...
rst    : POR
config : first use, defaults written (color=green, brightness=100)
flash  : ID = EF4019, 4-byte address mode
log    : 0 record(s), ring 1048320 slots
sensor : AP3216C ok, MPU6050 ok (ID=0x68)
rtc    : ...
rtos   : starting scheduler...
```

> `config : first use` 只在配置格式升级/首次上电出现一次；
> 若每次上电都出现，说明 EEPROM 写入失败（查 0x50 与 I2C4）。

| 检查 | 预期 | 实测 |
|---|---|---|
| 无复位循环 | 首屏只出现一次，之后每 3 s 一行监测 | ☐ |
| `vTaskList` 含 10 个任务 | ENV/MOT/UI/CON/LOG/LED/MON/HLTH/IDLE/Tmr Svc | ☐ |
| 心跳灯 | 500 ms 周期（示波器/逻辑分析仪） | ☐ |

可选压测脚本（`pip install pyserial`，把 COM5 换成实际端口）：

```python
import serial, time
s = serial.Serial("COM5", 115200, timeout=1)
time.sleep(0.2)
for i in range(200):
    s.write(b"info\r\n")
    time.sleep(0.05)
time.sleep(1)
print(s.read(200000).decode("utf-8", "replace").count("fw"))
```

## 4. G4 日志（掉电安全）

| 项 | 步骤 | 判据 | 实测 |
|---|---|---|---|
| 基本写入 | 跑 10 s 后 `> dump 5` | 5 条，seq 连续，时间/数据合理 | ☐ |
| 逻辑擦除 | `> erase` 再 `> status` | count=0、seq 从 0 重来、采样不中断 | ☐ |
| **断电 ×3** | 跑 30 s → 拔电 → 上电，重复 3 次 | 每次 `log` 计数 ≈ 运行秒数×20（最多丢最后 2 s），`dump` 尾部 seq 连续 | ☐ |
| 写后立刻断电 | 上电 3 s 内拔电，重复 5 次 | 每次都能恢复，无"卡在 log : scan failed" | ☐ |
| 跨页写 | 正常跑 2 min 后 `> dump 64` | 无 `ERR log read failed (4)`（CRC 全过） | ☐ |
| 环形覆盖 | `log.h` 里 `LOG_TEST_SMALL_DATA` 改 1 → 重编译 → 跑 3 min → `dump 20` | seq 连续、无 CRC 错、旧记录被整扇区回收 | ☐ |
| evtQueue 优先 | `> logpause on` → 等 `drop` 增长（约 7 s）→ 遮光触发报警 → `> logpause off` → `> dump 10` | 报警记录（flags 含 `0x0010`）紧接上一批落盘，不因队列满而丢 | ☐ |

> 测完把 `LOG_TEST_SMALL_DATA` 改回 `0` 并重新编译，再继续后面的项。

## 5. G5 报警与 UI

### 5.1 光照两段式

| 步骤 | 判据 | 实测 |
|---|---|---|
| `> alarm` 记下阈值；`> live 1` 看当前 ALS | 记录 ALS 值 | ☐ |
| 遮住传感器 **0.5 s** 后松开 | **不报警**（红灯不闪、蜂鸣器不响） | ☐ |
| 遮住 **≥1.2 s** | 红灯 100 ms 快闪 + 蜂鸣器 200/300 ms 间歇 | ☐ |
| 触发后 `> alarm` | `light=1`，且 `last confirm->action = xx ms` **≤100** | ☐ |
| `> alarm clear` 或按 KEY2(PC13) | 红灯灭、蜂鸣停、`alarm` 显示 light=0 | ☐ |

### 5.2 运动两段式

| 步骤 | 判据 | 实测 |
|---|---|---|
| 拿起板子轻碰一下 | 不报警 | ☐ |
| 连续晃动 ≥1.2 s | 红灯快闪 + 蜂鸣 | ☐ |
| `> alarm` | `motion=1`，延迟 ≤100 ms | ☐ |
| `> alarm clear` / KEY2 | 报警清除 | ☐ |

### 5.3 静音 / 按键 / 配置

| 项 | 步骤 | 判据 | 实测 |
|---|---|---|---|
| 手动静音 | 报警中 `> alarm mute` 或按 KEY1(PA0) | 蜂鸣停、红灯继续 | ☐ |
| 解除静音 | 再按 KEY1 / `> alarm unmute` | 蜂鸣恢复 | ☐ |
| 30 s 自动静音 | 触发后不操作，等 30 s | 蜂鸣停、红灯仍闪 | ☐ |
| 阈值调整 | `> cfg thr 30 1500` → 遮光 | 触发变难/变易符合预期 | ☐ |
| 采样周期 | `> cfg rate 100` → `> live 1` | 快照间隔约 100 ms | ☐ |
| 持久化 | `> cfg save` → 断电 → 上电 `> cfg show` | 修改后的值仍在 | ☐ |

## 6. Step 8：健康监控与 IWDG

| 项 | 步骤 | 判据 | 实测 |
|---|---|---|---|
| 健康状态 | `> status` | `health=1`、`last_fail=255` | ☐ |
| 看门狗复位 | `> wd test 5` | 约 2 s 后板子复位；重启首屏 `rst : ... IWDG` | ☐ |
| 复位原因 | 上电后 `> status` | `reset flags` 含 `IWDG` | ☐ |
| 长跑 ≥2 h | 静置 2 h，每小时 `> status` | 无复位、`health=1`、`drop=0`、`up=` 连续 | ☐ |

> **注意**：IWDG 超时 2 s，调试器暂停超过 2 s 会复位芯片——这是正常行为，不要当故障。

### 6.1 故障注入三连

| 注入 | 做法 | 预期 | 实测 |
|---|---|---|---|
| 栈溢出 | `main.c` 里 LED 任务栈 `128u` 改 `64u` → 重编译烧录 | 打印 `!! STACK OVERFLOW: LED` 并停住（2 s 后被 IWDG 复位）；改回 128u | ☐ |
| 队列灌满 | `> logpause on` 等 10 s → `> logpause off` | `drop` 先增长、恢复后停止；报警事件仍能落盘 | ☐ |
| I2C 不加锁 | `bsp_i2c_bus.h` 里 `I2C_LOCK_TEST_SKIP` 改 1 → 重编译 → 同时 `> sensor` 与 `> cfg save`，反复 100 次 | 出现偶发 NACK（flags 的 ERR 位），对照加锁版本为 0；测完改回 0 | ☐ |

## 8. 现象判读：这些不是 bug

| 现象 | 解释 |
|---|---|
| 首屏 `config : first use` | 配置格式从 `P0LG` 升到 `P0L2`，旧配置按首次使用处理 |
| `dump` 只有最近 14.5 h | 32 MB 环形日志的滚动窗口，属设计值 |
| 蓝闪几乎看不见 | 写盘一批只需几毫秒，UiTask 50 ms 轮询通常会错过 |
| 报警后红灯一直闪 | 报警是锁存式，30 s 只静音不停报警，需 `alarm clear` / KEY2 |
| 上电蜂鸣器一直响 | 蜂鸣器极性假设反了，把 `ui_task.c` 的 `BUZZER_ACTIVE_HIGH` 改 0 |
| 按键无反应 | 检查 PA0/PC13 是否被底板跳线占用；`i2c scan` 不受影响说明 MCU 正常 |
| 调试暂停后板子重启 | IWDG 超时 2 s，预期行为 |
| `wd test` 后串口断一下 | MCU 复位，终端需重新连接 |
