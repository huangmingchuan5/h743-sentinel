# 32 B 快照日志：格式、写入与掉电恢复

> 对应代码：`App/log/log.c` / `log.h`、`BSP/flash/bsp_qspi_flash.c`
> 存储介质：W25Q256（32 MB，QSPI，4 字节地址模式），页 256 B、扇区 4 KB

---

## 1. 为什么要"定长 + 双副本"

- **定长 32 B**：环形寻址只需要 `addr = BASE + seq × 32`，不需要索引表；掉电后也能逐条扫描校验。
- **双副本元数据**：检查点本身也会被写坏，A/B 两份轮流写，任何时刻至少有一份可用。
- **数据先写、检查点后提交**：检查点落后于数据最多"一批（32 条 / 2 s）"，恢复时靠 seq 连续性把这段补回来。

---

## 2. 记录格式（32 Byte）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 4 | `seq` | 全局递增序号，由 LoggerTask 在写盘时统一分配 |
| 4 | 4 | `tstamp` | `flags.bit15=1` → 2000-01-01 起的秒数；`=0` → 上电 tick（ms） |
| 8 | 2 | `als` | AP3216C 环境光原始值 |
| 10 | 2 | `ps` | 低 10 位 = 接近原始值，bit15 = "接近"标志 |
| 12 | 2 | `ax` | 加速度 X（±4 g，8192 LSB = 1 g） |
| 14 | 2 | `ay` | 加速度 Y |
| 16 | 2 | `az` | 加速度 Z |
| 18 | 2 | `flags` | 见下表 |
| 20 | 10 | `rsv` | 保留（当前填 0） |
| 30 | 2 | `crc` | CRC-16/CCITT-FALSE，覆盖前 30 字节 |

**编译期断言**：`sizeof(Sample_t) == 32`，结构体一不小心被填充字节撑大就直接编译失败。

### flags 位定义

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | `SAMPLE_F_ALS_ERR` | 本拍 ALS 读取失败 |
| 1 | `SAMPLE_F_PS_ERR` | 本拍 PS 读取失败 |
| 2 | `SAMPLE_F_PS_OVF` | PS 溢出（物体很近 / 强红外） |
| 3 | `SAMPLE_F_ACC_ERR` | 本拍加速度读取失败 |
| 4 | `SAMPLE_F_EVT_LIGHT` | 事件记录：光照报警触发 |
| 5 | `SAMPLE_F_EVT_MOTION` | 事件记录：运动报警触发 |
| 6 | `SAMPLE_F_EVT_CLEAR` | 事件记录：报警被清除 |
| 15 | `SAMPLE_F_TS_REAL` | 时间戳是 RTC 日历时间（否则为上电 tick） |

### CRC 参数

`CRC-16/CCITT-FALSE`：初值 `0xFFFF`、多项式 `0x1021`、不反射、无最终异或。
记录 CRC 覆盖 `[0, 30)`；检查点 CRC 覆盖 `[0, 62)`。

## 3. Flash 布局（32 MB）

| 区域 | 地址范围 | 大小 | 用途 |
|---|---|---|---|
| 元数据 A | `0x0000_0000 – 0x0000_0FFF` | 4 KB | 64 个检查点 × 64 B |
| 元数据 B | `0x0000_1000 – 0x0000_1FFF` | 4 KB | 64 个检查点 × 64 B |
| 数据环 | `0x0000_2000 – 0x01FF_FFFF` | 32 MB − 8 KB | 1,048,320 条 × 32 B |

### 检查点格式（64 Byte）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 4 | `magic` | `0x534E5431`（"SNT1"） |
| 4 | 2 | `version` | 当前 1 |
| 6 | 2 | `reserved` | 0 |
| 8 | 4 | `epoch` | 每次逻辑擦除 +1（区分新旧盘的检查点） |
| 12 | 4 | `wrAddr` | 下一条记录的绝对地址 |
| 16 | 4 | `seqNext` | 下一条记录的序号 |
| 20 | 4 | `recTotal` | 本次 erase 以来累计写入条数（可大于环容量） |
| 24 | 38 | `rsv` | 保留 |
| 62 | 2 | `crc` | CRC-16/CCITT-FALSE，覆盖前 62 字节 |

## 4. 写入路径（LoggerTask，优先级 2）

```
ulTaskNotifyTake(pdTRUE, 剩余超时)          ← 采样/报警投递后通知
  ├─ 先清空 evtQueue（报警事件优先）
  ├─ 再收 logQueue，最多凑 32 条（1 KB）
  └─ 达到 32 条 或 距上次写盘 ≥ 2 s → 写一批
        ├─ 取 flashMutex（1 s 超时），置 EVT_FLASH_BUSY
        ├─ 逐段写：
        │    若 addr 在扇区起点 → 先擦除该扇区（环形覆盖时它就是最旧数据）
        │    room = min(本页剩余, 本批剩余, 数据区末尾 − addr)
        │    给本段记录分配 seq、计算 CRC
        │    Flash_PageWrite(addr, buf, room)
        │    Flash_Read 回读 + memcmp 逐字节校验
        ├─ 每 256 条 或 30 s → 提交一次检查点
        └─ 清 EVT_FLASH_BUSY，释放 flashMutex
```

**为什么不会跨页/跨扇区**

- 页 256 B、扇区 4 KB、记录 32 B，三者整除；
- 每次 `room` 都夹在"本页剩余"之内，所以一条页写命令不会跨页；
- 页边界必然也是扇区边界（4 KB = 16 页），所以也不会跨扇区。

**跨页写怎么验**：一批 32 条 = 1024 B，从任意 32 B 对齐地址开始都会跨 4 个页，
正常写日志本身就在持续制造跨页写；`dump` 会逐条校验 CRC，读回不一致会直接报错。

## 5. 检查点提交与 A/B 轮换

```
当前副本 offset + 64 ≤ 4 KB ?
  ├─ 是：写 64 B → 读回 memcmp → 成功才 offset += 64
  └─ 否：1) 确认"当前副本"里存在有效检查点（没有就报错，绝不擦另一份）
          2) 擦除另一份所在扇区（它保存的是更早的检查点，不是最新的）
          3) 切到另一份，offset = 0
          4) 写新检查点并读回校验
```

**安全性质**：切换过程中，最新有效检查点始终留在"当前副本"里；
另一份即使被擦到一半掉电，也只损失更早的回退点，不会让整盘不可恢复。

**触发时机**：每写 256 条，或距上次提交 ≥ 30 s；回卷到数据区开头前强制提交一次。

## 6. 启动恢复（Log_Init）

```
1. 在 A、B 两份里各找"最后一个 magic/version/CRC 都正确"的检查点
2. 两份都有效 → 取 (epoch, seqNext) 更大的一份
   只有一份有效 → 用它
   都无效       → 当作新盘：擦 A/B，epoch=1，wrAddr=BASE，seq=0
3. 校验 wrAddr：必须落在数据环内且 32 B 对齐，否则按新盘处理
4. 从 wrAddr 开始向前扫描：
     记录 CRC 有效 且 seq == seqNext + 已扫描数 → 收下，seqNext++，recTotal++
     遇到第一条不合法记录 → 停止
5. 扫描到的条数就是"数据已写、检查点未提交"的部分，恢复完成
```

**掉电语义**

| 掉电时刻 | 结果 |
|---|---|
| 数据写了一半 | 该条 CRC 不匹配 → 扫描停止，丢掉半条 |
| 数据写完、检查点没提交 | 扫描时被 seq 连续性捞回来 |
| 检查点写坏 | 读回校验失败 → 不推进 offset；重启后取上一份有效检查点 |
| 擦除另一份时掉电 | 最新的那份仍在，恢复不受影响 |

## 7. 容量与保留时长

| 项 | 数值 |
|---|---|
| 数据区 | 32 MB − 8 KB = 33,546,240 B |
| 单条 | 32 B |
| 容量 | 1,048,320 条 |
| 默认速率 | 20 Hz（50 ms） |
| 保留窗口 | 1,048,320 ÷ 20 ≈ 52,416 s ≈ **14.56 h** |
| 10 Hz | ≈ 29.1 h |
| 5 Hz | ≈ 58.2 h |

> 时间戳来自 RTC 日历；未校时则退化为上电 tick（`flags.bit15 = 0`），
> 两种语义必须靠这一位区分，不能混着算。

## 8. 命令与测试钩子

| 命令 | 作用 |
|---|---|
| `dump [n\|all]` | 从"可读窗口"尾部倒着取 n 条，8 条一批读 + 打印（锁不跨输出） |
| `erase` | **逻辑擦除**：epoch+1、指针归零、立即提交检查点；不整片擦 32 MB，秒级完成 |
| `logpause on/off` | 暂停消费，让 logQueue 灌满（验证 evtQueue 优先级） |
| `qtest` | QSPI 16 MB 边界读写测试（4 字节地址模式） |

### 覆盖测试开关

`log.h` 里把 `LOG_TEST_SMALL_DATA` 改成 `1`，数据环缩到 8 个扇区（32 KB，约 51 s 一圈），
跑 3 分钟后 `dump 20` 检查 seq 连续、CRC 正常；测完改回 `0` 重新编译。

## 9. 已知边界

- `recTotal` 会一直累加，超过 32 位（约 68 年 @20 Hz）才会回绕；
- 环形覆盖按"整扇区回收"：写满一圈后，最旧的 128 条会被整扇区擦掉，不是逐条覆盖；
- 逻辑擦除后旧数据仍在 Flash 里（未擦除），需要物理擦除请用 `qtest` 之外的整片擦除流程；
- Flash 写入期间 `EVT_FLASH_BUSY` 置位，UiTask 会切蓝闪；写入很快，肉眼通常看不到。
