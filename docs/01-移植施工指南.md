# H743 Sentinel 施工指南（基于 demo1_5 + 手动移植 FreeRTOS）

> 本指南是"施工执行版"：保留移植前基线工程的 HAL 库与 BSP，手动把 FreeRTOS 移植进来，
> 再按步骤把项目升级成 Sentinel（多任务环境与姿态监测记录仪）。
>
> 配套文档：
> - 设计与验收（做什么）：《H743-RTOS大项目题目与学习指南.md》v1.1
> - 移植原理与细节（为什么）：《H743-RTOS项目-从零构建指南.md》
> - 本指南（怎么做、怎么交给 AI 做）：按 Step 0~8 执行。
>
> **本指南 v1.1 修订（第二轮回审采纳）**：
> - 新增"开工前配置核对表"（0.1）：Include Paths 必须含 portmacro.h 所在目录、任务通知、事件组（V9 无对应宏，靠 event_groups.c）、vTaskList 前置条件、优先级与中断一致性；
> - 明确编译工具链：**保持当前工程的 AC5 + MicroLIB**（已核实本工程为 V5.06u7、uAC6=0、useUlib=1），不要为了移植切换 AC6；
> - LoggerTask 唤醒改为"任务通知 + 双队列"（logQueue/evtQueue 有新数据都通知它，报警优先处理）；
> - Step 5 增加 RTC 独立小节（time set、LSE/VBAT、掉电保持验证、失败回退规则）；
> - Step 6 增加三条硬规则：元数据"先写新副本并校验成功，才允许擦旧副本"、跨页写必须切片（已核实 Flash_PageWrite 不跨页）、保留时长如实说明（约 14~15h）；
> - G1 的 tick 校验改为"比较一段时间内的增量/速率"，不再比较绝对值。
> 说明：本文中的 `demo1_5` 指移植前的裸机基线工程，该基线的工程文件已在发布版仓库中移除，
> 仅作历史说明；文中所有路径均指**本仓库根目录**。

## 0. 这份指南怎么用（AI 协作协议）

**前置准备（10 分钟）**
1. 工程位于 `仓库根`（原 `demo1_5` 只读参考；Keil 工程文件：`MDK-ARM\demo2_1.uvprojx`）；
2. 在该目录建 Git 基线，先提交一次 `baseline`（之后每完成一步 commit 一次）；
3. 打开 Keil，确认能编译、能下载、串口输出与 demo1_5 一致（基线可跑）。

**和 AI（Codex 等）协作的规则**
- **一步一轮**：一次只做本指南里的一个 Step；做完、验收通过，再进入下一步。
- **先方案后改码**：每步先让 AI 读指定文件、给"改动点清单 + 风险"，你确认后再让它给**最小 diff**；
  拒绝"重写整个工程/重写整个文件"的做法。
- **硬约束**（写进每一轮提示词里）：Keil 用 **AC5**；不改与当前步骤无关的模块；
  引脚/器件地址一律以 `H743对应资料` 的 IO 表和原理图、以及现有 BSP 代码为准；
  不引入新库、不升级 FreeRTOS 版本（全项目统一用野火例程里的 **V9.0.0**）。
- **AI 不做验收**：验收动作由你在板子上做（编译结果、串口输出贴回给 AI 分析）。
- **出错止损**：任何一步改崩了，`git checkout` 回上一步，再让 AI 给更小的改动。

### 0.1 开工前配置核对表（v1.1 新增）

引入 FreeRTOS 前先对照下表逐项确认（拿不准可以问 AI，但最终以你工程里的实际文件为准）：

| 检查项 | 应确认的内容 |
|---|---|

### Step 0　CubeMX 最后一次再生成，然后冻结

**目标**：让 CubeMX 把"HAL 时基迁到 TIM7"，并打开 USART1 中断；之后不再用 CubeMX 重新生成，全部手改。

**当前状态（已核实）**：`demo2_1.ioc` 仍是 Timebase=SysTick、USART1 中断未开、`stm32h7xx_it.c` 的 SysTick_Handler 还带 `HAL_IncTick()`——Step 0 尚未执行，按下面做。

**动作**（在 `demo2_1.ioc` 上操作）：
1. SYS → Timebase Source 从 `SysTick` 改为 **`TIM7`**（TIM6 已被呼吸灯占用，不能选它）；
2. NVIC：勾选 **USART1 global interrupt**（为 Step 4 的收发中断做准备）；
3. NVIC 里把 **TIM6_DAC 中断优先级改成 5**（统一策略；它现在可能是 0）；
4. Generate Code；
5. 检查生成结果：
   - 应出现 `Core/Src/stm32h7xx_hal_timebase_tim.c`（TIM7 喂 HAL tick）；
   - 打开 `Core/Src/stm32h7xx_it.c` 检查 `SysTick_Handler`：**若里面还有 `HAL_IncTick()`，删掉**（HAL tick 现在由 TIM7 提供）；
   - 编译下载，确认基线行为与之前一致（banner、命令台都正常）。

**AI 提示词**：
> 我的 Keil 工程由 CubeMX 生成（路径：仓库根）。我把 Timebase Source 从 SysTick 改成了 TIM7 并勾选了 USART1 全局中断，重新生成了代码。请检查要点：1) HAL 时基现在是否完全由 stm32h7xx_hal_timebase_tim.c 提供；2) stm32h7xx_it.c 的 SysTick_Handler 里是否残留 HAL_IncTick()（应该删掉）；3) USART1_IRQHandler 是否已生成。给出核对清单和需要手改的地方。

**验收**：工程可编译可下载；banner 和命令台正常；`TIM7_IRQHandler` 存在且调用了 HAL 的 tick 逻辑。

**坑**：改完时基后如果忘记删 SysTick 里的 `HAL_IncTick()`，HAL tick 会被"喂两次"——后面接了 FreeRTOS 会出现节拍混乱。

### Step 4　控制台任务化（门禁 G2）

**目标**：把"轮询控制台"改成"事件驱动任务 + 中断收发"。

**动作**（顺序执行，每小步都编译+测试）：
1. **RX 改造**：`Uart_ReadByte` 阻塞读 → USART1 中断收字节入 256B 环形缓冲，
   ISR 末尾 `vTaskNotifyGiveFromISR`；新任务 `ConsoleTask` 阻塞在 `ulTaskNotifyTake`，醒来取走缓冲里的全部字节，
   复用你现有的行编辑逻辑（退格/回显/超长丢弃）与 `Line_Execute/Dispatch`。
2. **TX 改造**：`fputc` 逐字节阻塞 → 新增 `Uart_TxIT(buf,len)`（HAL_UART_Transmit_IT）+
   发送完成回调给 `txDoneSem`；提供 `Uart_Printf(...)`：`uartMutex` → vsnprintf 到本地缓冲 →
   `Uart_TxIT` → 等 `txDoneSem` → 释放锁。任务代码统一改用 `Uart_Printf`；`printf/fputc` 只留给调度器启动前的 banner。
3. **长输出改造**：`dump/clear` 等命令输出分块（每次读一小批 → 释放 flashMutex → 打印 → 继续），
   锁不跨输出（v1.1 修订核心，别漏）。
4. 删除旧 `Console_Task` 轮询调用；验证命令行为与 demo1_5 一致（大小写不敏感、错误提示、回显）。

### Step 6　日志系统（v1.1 设计，门禁 G4）

**目标**：把旧 `App/log`（64B 线性 256 条）升级为 **32B 快照 + 元数据双副本 + 环形覆盖**。

**动作**：
1. 记录格式 32B：`seq(4)+时间戳(4)+als(2)+ps(2)+ax/ay/az(6)+flags(2)+保留(10)+CRC16(2)`；`seq` 由 LoggerTask 统一分配。
2. Flash 布局：扇区 0/1 = 元数据副本 A/B（64B 追加式检查点）；扇区 2 起 = 数据环。
   检查点含 magic/版本/写指针/最新 seq/CRC；提交策略：每 256 条或 30s 一次；A 满转 B、B 满擦 A——**轮换擦除**。
   **擦除顺序硬规则**：新检查点必须"写入另一份并从 Flash 读回校验成功"之后，才允许擦除旧副本所在扇区；
   任何时刻保证至少一份有效元数据；恢复时取最新有效版本。
3. 启动恢复：取最新有效检查点 → 向后扫描（CRC+seq 连续）恢复真实写指针，兼容"数据已写、检查点未提交"。
4. `LoggerTask`（优先级 2）——**唤醒与批量规则（v1.1 指定）**：
   - 唤醒源用**任务通知**：采样任务入队后 `xTaskNotifyGive()`；报警路径（或 ISR 内）用 `vTaskNotifyGiveFromISR()`；
     凡向 `logQueue` 或 `evtQueue` 投递过数据，都要通知一次；
   - LoggerTask 用 `ulTaskNotifyTake(pdTRUE, 剩余超时)` 阻塞：醒来**先清空 `evtQueue`（报警优先落盘），再收集 `logQueue`**；
   - 达到 32 条或距上次写盘 2s（写盘超时）即执行批量写入；剩余超时 = 2s − 已等待时间；
   - 说明：V9 也可用队列集（需 `configUSE_QUEUE_SETS=1` 并注册队列）实现"同时阻塞两个队列"；
     本项目选更直观的"任务通知 + 双队列"方案，便于调试。
5. 环形覆盖：写满后回收最旧完整扇区（先做线性追加跑稳，再切环形；共用恢复逻辑）。
6. `dump <n|all>` / `erase` 命令改造：分块读 + 分块打印（接 Step 4 的 TX 通道）。
7. **跨页写（已核实必须处理）**：W25Q256 页 = 256B；你的 `Flash_PageWrite()` 只发一条 ≤256B 的页写、**不做跨页拆分**。
   32 条 × 32B = 1024B 的一批至少跨 4 页，必须在日志层（或在 BSP 加一层 `Flash_WriteNoCross()` 包装）按"到本页末尾的剩余长度"切片，
   每段单独调用 `Flash_PageWrite`；同时保证写入不跨擦除扇区边界。验证用例：从未对齐地址（如 0x010100）写 1024B，读回逐字节校验。
8. **保留时长如实说明**：20 条/s × 32B = 640 B/s，32MB ≈ **14~15 小时**滚动窗口（再扣元数据区）。
   演示文档与答辩材料必须写明"设备可长期运行，但历史可回溯约 14~15 小时"；想延长就把快照降为 10Hz（≈29h）或 5Hz（≈58h）。
9. 验证：断电×3 连续；"写后立刻断电"能恢复；跨页写测试；可临时缩小数据区做覆盖测试。

**AI 提示词**：
> 现在做日志系统升级（涉及 BSP\flash 与 App\log）。设计要求 [附上面 1~6]。
> 请先给出：1) 记录/检查点的字节级布局表；2) 写入与提交的状态机（含掉电安全顺序）；3) 启动恢复流程；4) LoggerTask 伪代码。全部确认后再给代码。

**门禁 G4**：断电×3 连续（含"写后立刻断电"）；跨页写 1024B 校验通过；元数据擦除顺序符合"先新后旧"；覆盖测试通过；
evtQueue 优先级验证（灌满 logQueue 后报警事件仍能落盘）；导出压力指标（dropped=0、队列峰值≤50%、健康计数正常——HealthTask 在 Step 8 前用临时计数器代替）。

### Step 7　报警 / UI / 按键 / 配置扩展（门禁 G5）

**动作**：
1. `evtQueue`（16 槽）+ 事件组 `sysEvents`（ALARM_LIGHT / ALARM_MOTION / FLASH_BUSY / SAMPLING_PAUSED / LOG_FULL）；
2. 阈值判定：EnvTask 光报警（确认窗 1s）、MotionTask 运动报警；命中 → 置事件位 + `evtQueue` 投递 ALARM 事件；
3. `UiTask`（优先级 4）：等事件组（超时 50ms）→ 管理灯模式（绿呼吸由 TIM6 继续；蓝闪=写盘；红快闪=报警）、蜂鸣器 PI8 间歇、按键；
   LED 状态变量与 TIM6 ISR 之间用临界区保护（几字节拷贝）；
4. 按键：PA0/PC13 EXTI → `vTaskNotifyGiveFromISR` → UiTask（消抖在任务里）；

6. 配置扩展：EEPROM 增加 rate/thr 字段（magic+CRC），`cfg save/load/reset`；
7. 验证：**两段式**——遮光 1s 确认窗内不动作；确认后 ≤100ms 声光启动（记录两个时间戳）；晃动同理；`alarm clear/mute` 生效。
