# 任务、优先级与同步对象设计

> 对应代码：`Core/Src/main.c`（创建顺序）、`App/sample`、`App/log`、`App/console`、`App/system`
> 内核：FreeRTOS V9.0.0，`configTICK_RATE_HZ = 1000`（1 tick = 1 ms），`configMAX_PRIORITIES = 32`

---

## 1. 设计原则

1. **优先级按"截止时间"排，不按"重要性"排**：越不能等的事情优先级越高（采样 > 表现 > 记录 > 监控）。
2. **周期任务用 `vTaskDelayUntil`**：以固定节拍唤醒，避免"处理耗时"累积成漂移。
3. **事件任务只阻塞、不轮询**：控制台、日志任务都阻塞在队列/通知上，没有数据时不占 CPU。
4. **临界区只保护"几字节拷贝"**：I2C 事务、Flash 写入这类慢操作一律用互斥量，绝不进临界区。
5. **中断只做"搬运 + 通知"**：USART1 收字节、EXTI 按键都只投递通知，解析/消抖在任务里做。

## 2. 任务表

| 任务 | 优先级 | 栈（word / Byte） | 唤醒方式 | 健康窗口 | 职责 |
|---|---|---|---|---|---|
| `ENV` | 6 | 160 / 640 | `vTaskDelayUntil` 100 ms | 400 ms | 读 ALS/PS → 环境缓存 + 光照判定 |
| `MOT` | 5 | 160 / 640 | `vTaskDelayUntil` 50 ms（可配） | 500 ms | 读加速度 → 32 B 快照入队 + 运动判定 |
| `UI` | 4 | 384 / 1536 | 事件组 50 ms 超时 + 任务通知 | 400 ms | 灯效、蜂鸣器、按键消抖、延迟统计 |
| `CON` | 3 | 512 / 2048 | 任务通知（1 s 超时保活） | 2500 ms | 行编辑、命令解析、打印 |
| `LOG` | 2 | 320 / 1280 | 任务通知（2 s 超时冲刷） | 6000 ms | 双队列收集 → 批量写 Flash → 提交检查点 |
| `LED` | 2 | 128 / 512 | `vTaskDelayUntil` 500 ms | 2500 ms | 心跳灯（白光） |
| `MON` | 2 | 256 / 1024 | `vTaskDelay` 3 s | 5000 ms | tick/HAL tick 增量、heap、`vTaskList` |
| `HLTH` | 1 | 256 / 1024 | `vTaskDelay` 1 s | — | 汇总判据 → 喂 IWDG |
| `IDLE` | 0 | 128 / 512 | 就绪即运行 | — | 内核空闲任务（回收已删除任务/低功耗钩子） |
| `Tmr Svc` | 2 | 256 / 1024 | 定时器命令队列 | — | 软件定时器（30 s 自动静音） |

**为什么这样排**

- `ENV`/`MOT` 是数据源头，晚了就丢采样点，所以最高；
- `UI` 直接对应用户可感知的声光，必须比"记录"和"打印"先跑；
- `LOG` 只要队列不溢出（128 槽 ≈ 6.4 s）就可以慢慢写，放在 2；
- `MON` 与 `LED` 同为 2，靠时间片轮转，打印不会挡住写盘；
- `HLTH` 最低（1），它只做"检查 + 喂狗"，任何业务任务都比它重要；
- 定时器服务任务默认 31 会抢占一切，本项目在 `FreeRTOSConfig.h` 里改成 **2**。

## 3. 中断优先级

NVIC 使用 4 位优先级（`HAL_Init()` 默认分组 4），`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5`。

| 中断 | 优先级 | 说明 |
|---|---|---|
| TIM6_DAC（呼吸灯） | 5 | 10 ms 推进呼吸/闪烁 |
| TIM7（HAL 时基） | 5 | 1 ms 喂 `HAL_IncTick()` |
| USART1 | 5 | 收字节 → 环形缓冲 → `vTaskNotifyGiveFromISR` |
| EXTI0（PA0 / KEY1） | 5 | 按键 → 通知 UiTask |
| EXTI15_10（PC13 / KEY2） | 5 | 按键 → 通知 UiTask |

**规则**：只要中断里调用了 `...FromISR()`，优先级数值必须 **≥ 5**（数值越大优先级越低）。
低于 5 的中断不受内核临界区屏蔽，也就不能调用 FreeRTOS API。

## 4. 同步对象清单

| 对象 | 类型 | 创建位置 | 保护/传递什么 | 超时 |
|---|---|---|---|---|
| `uartMutex` | 互斥量 | `Uart_RtosInit()` | 多任务共享 USART1 发送 | 1000 ms |
| `txDoneSem` | 二值信号量 | `Uart_RtosInit()` | `HAL_UART_TxCpltCallback` → 等待发送完成 | 100 ms |
| `i2cMutex` | 互斥量 | `I2cBus_Init()` | I2C4 总线（EEPROM + 两个传感器） | 100 ms |
| `flashMutex` | 互斥量 | `Log_Start()` | QSPI Flash 读/写/擦 | 1000 ms |
| `logQueue` | 队列 | `Sample_Start()` | 32 B 快照：采样 → 日志 | 发送 0（满则丢并计数） |
| `evtQueue` | 队列 | `Log_Start()` | 报警事件快照（优先落盘） | 发送 0 |
| `sysEvents` | 事件组 | `AppEvents_Init()` | 报警/写盘/日志满/采样暂停状态位 | — |
| UiTask 通知 | 任务通知 | `Ui_Start()` | EXTI → 按键事件 | — |
| ConsoleTask 通知 | 任务通知 | `Console_Init()` | USART1 RX → 有新字节 | — |
| LoggerTask 通知 | 任务通知 | `Log_Start()` | 两个队列有新数据 | — |
| `s_muteTimer` | 软件定时器 | `Alarm_Init()` | 30 s 自动静音（单次） | — |

**为什么不用队列集（Queue Set）**：V9 支持队列集，但需要 `configUSE_QUEUE_SETS=1` 并注册队列；
本项目改用"任务通知 + 双队列"，LoggerTask 醒来先清 `evtQueue` 再收 `logQueue`，
逻辑更直观、调试时也更容易看出是"谁叫醒了我"。

## 5. 栈与堆预算

任务栈单位是 **word（4 Byte）**，`configMINIMAL_STACK_SIZE = 128`。

| 项 | 估算 |
|---|---|
| 全部任务栈 | 512 + 1024 + 2048 + 640 + 640 + 1280 + 1536 + 1024 + 512 + 1024 ≈ **10.2 KB** |
| 队列 | logQueue ≈ 4.2 KB + evtQueue ≈ 0.6 KB + 定时器命令队列 ≈ 0.6 KB |
| TCB / 互斥量 / 事件组 / 定时器 | ≈ 1.5 KB |
| 合计 | ≈ **17 KB**，`configTOTAL_HEAP_SIZE = 48 KB`，余量约 30 KB |

**栈水位怎么读**：`MON` 任务每 3 s 打印 `vTaskList()`，最后一列 `Stack` 是
`uxTaskGetStackHighWaterMark()` 的结果（单位 word，表示"历史最小剩余量"）。
连续跑 2 h 后该值仍 > 20% 栈深，就认为安全。

## 6. 调度时序（稳态）

```
每 1 ms   TIM7 → HAL_IncTick                 （HAL 时基，不参与调度）
每 10 ms  TIM6 → 呼吸灯/闪烁推进              （中断里直接写 CCR，不唤醒任务）
每 50 ms  MOT 醒 → 读 MPU6050 → 入队 → 通知 LOG → 报警判定 → 报活
每 100 ms ENV 醒 → 读 AP3216C → 更新缓存 → 报警判定 → 报活
每 50 ms  UI 醒（或被事件组/按键叫醒）→ 切灯效 → 蜂鸣器 → 报活
事件驱动  CON：串口有字节才醒；LOG：队列有数据才醒
每 500 ms LED 心跳；每 1 s HLTH 判据 + 喂狗；每 3 s MON 打印
```

关键点：**没有忙等**。所有任务在无事可做时都阻塞在内核对象上，CPU 空闲时间留给 `IDLE`。

## 7. 容易踩的坑（本工程已踩过）

| 坑 | 原因 | 规避 |
|---|---|---|
| 调度器启动前创建 RTOS 对象后中断全灭 | `xQueueGenericReset` 进临界区，`uxCriticalNesting` 初值是哨兵 `0xaaaaaaaa`，退出时不清 BASEPRI | 所有"创建类"调用之后显式 `__set_BASEPRI(0)`，再初始化依赖中断的外设 |
| 在临界区里做 I2C | 关中断时间过长，TIM6/TIM7 丢节拍 | 临界区只做结构体拷贝；总线访问用 `i2cMutex` |
| 中断里 `printf` | 阻塞发送，且在 ISR 里等信号量 | ISR 只投递通知，打印全部在任务里 |
| 任务通知被"覆盖" | 通知值是计数语义，`ulTaskNotifyTake(pdTRUE, …)` 一次清空 | 醒来后把缓冲区里的字节**全部**取走，不假设"一次通知 = 一个字节" |
| `vTaskDelayUntil` 初值取错 | 用 0 或任务创建时刻之外的 tick | 进入循环前 `lastWake = xTaskGetTickCount()` |
| IWDG 与调试器冲突 | 断点暂停 > 2 s 就复位 | 调试时用 `wd test` 之外的方式验证；或临时注释 `Health_Start()` 里的 IWDG 初始化 |
